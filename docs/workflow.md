# 日常流程

1. 發現文獻後先查 DOI；與 papers.csv 的 DOI 比對，再檢查標題、作者及年分。DOI 大小寫、網址前綴差異不代表不同文獻。
2. 無 DOI 時以標題＋第一作者＋年分人工去重；預印本和正式發表原則保留正式版本主記錄，在筆記標明版本關係。只有確需比較不同版本時才分開建檔並相互連結。
3. 建立 paper_id，填必填欄位；reading_status=inbox。先不填未核對資訊。
4. 閱讀標題摘要後改 screened 或 excluded；排除時記錄理由。正式閱讀改 reading。
5. 複製筆記模板到 notes/<paper_id>.md；閱讀完成才改 read。摘要與部分閱讀不得標成完成全文閱讀。
6. 將論文連到一或多個 projects，必要時補專案矩陣。矩陣只存與該專案有關的提煉，書目資料回查主表。
7. 更新 updated_on，執行 python3 scripts/validate.py；核對公開內容後才自行決定是否提交。

## 使用試算表
用 Excel「從文字／CSV」以 UTF-8 匯入，將 ID、DOI、日期等先當文字。以逗號分隔 CSV UTF-8 匯出，不可任意改成分號分隔。保留原欄名與順序；不要將主表改成 xlsx 當唯一來源。

## 引用與期刊分區
主表是索引，筆記是證據，專案矩陣是寫作選材。文獻管理器可另存 BibTeX／RIS；如需匯入，以 DOI 或 citekey 對應主表，避免雙邊各自維護不同書目版本。
不將 Q1 當永久標籤；若日後追蹤分區，須另記 JCR 年度、學科類別、來源與查核日期，不能憑期刊名稱推定當年分區。

## 交由助理整理

在 ChatGPT 提供 PDF、DOI 或論文連結及所屬專案。助理核對、去重後更新主表、筆記及適用矩陣，再更新私人網站的資料快照。網站不會自行分析文獻；必須在對話中提出新增要求。網站中的示例與正式資料完全分開，不會寫入主表。

目前 repository 公開；在改為私人之前，只加入可公開書目與模板。詳細閱讀筆記或未發表構想不得寫入公開庫。改為私人後，網站可由助理重新整理快照再部署；不在瀏覽器中放 GitHub token。
